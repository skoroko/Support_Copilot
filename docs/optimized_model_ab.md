# Mini и Luna medium на оптимизированном коде — 15.10.2026

## Зафиксированный до запуска протокол

Два прежних реальных вопроса с соответствующей замороженной историей:
обзор Hardening Soil (`0801f604b07c`) и граничные условия GTS NX
(`a7b5f7c44544`). По три ответа каждой модели на каждый вопрос: 12 ответов.
Никакие expansion-команды не используются. Приложение и production-модель
не меняются. Из истории обеим моделям удаляются только provider metadata,
включая encrypted reasoning; тексты и последовательность сообщений сохранены.

Профили соответствуют прежнему mini и текущей Luna: GPT-5.4 mini,
Chat Completions, none (API default), temperature 0, cap 500; GPT-6 Luna,
Responses, medium, temperature не передаётся, общий generation cap 8692
(500 + 8192 reserve). Одинаковая инструкция краткого ответа; reasoning reserve
не задаёт отдельный жёсткий лимит видимого ответа. Mini none подтверждён
[официальной модельной страницей](https://developers.openai.com/api/docs/models/gpt-5.4-mini).
Это A/B runtime-профилей, а не изоляция влияния только весов модели.

Concurrency 1. Каждый ответ — свежий процесс, одинаково холодные Python-кеши;
общие filesystem/provider caches не сбрасываются. Порядок моделей чередуется,
первое место меняется между вопросами и повторами. Сохраняются все времена,
usage, call counts, evidence и ошибки. Эталоны не подаются испытуемым моделям.
Данные остаются в ignored var; в Git — только обезличенные метрики/оценки.

## Рубрика, зафиксированная до ответов

Ручная содержательная оценка исполнителем Astra, без модели-judge. Источники:
GTS NX User Manual Chapter 5, вводная классификация Boundary (physical p32,
printed31); GTS_NX2021 CHM, Materials/HS small strain; User Manual Chapter4
Mesh (physical66/printed65); русский мануал Materials (physical74/printed203).
Оценка опирается также на точный фрагмент каждой фактически приведённой цитаты.

Границы: по одному баллу за (B1) DOF/механические ограничения, (B2) seepage
boundaries для фильтрации, (B3) boundary elements для equivalent linear/
динамического анализа. Достаточно обзорной категории, полный каталог команд
не требуется. Дополнительные подробности не заменяют пропущенную категорию.
Отдельно проверяются ложные переносы drainage в фильтрацию, смешение нагрузки
с границами и неподтверждённые указания режима применимости.

HS: по одному баллу за (H1) честную область HS vs HS small strain, (H2)
нелинейную зависимость жёсткости/гиперболическое поведение, (H3) объяснение
small-strain эффекта/снижения жёсткости, (H4) хотя бы одну корректно объяснённую
группу существенных параметров (например G0/γ0.7 либо E50/Eoed/Eur/m), без
обязательного полного списка. Если обсуждается происхождение, требуется точное
«Modified Mohr-Coulomb», а не базовый Mohr-Coulomb. Не требуется утверждать
происхождение, чтобы получить полную обзорную оценку.

Для каждого ответа отдельно фиксируются: покрытие критериев; фактические
ошибки и их существенность; unsupported claims; правильность именования и
области; поддержка конкретных утверждений конкретными цитатами; incomplete.
Сопоставляются согласованность трёх повторов, медиана и диапазон времени.
P95, статистическая значимость и общий вывод о качестве на всех задачах не
заявляются. Стоимость не рассчитывается без отдельной проверки тарифов.

## Результат

**Рекомендация: оставить рабочую Luna medium.** Mini существенно быстрее,
но на этих двух вопросах менее надёжна по области применимости и качеству
дополнительного поиска. Production не переключалась: после эксперимента
проверены Luna medium для brief/expanded, `/ready` 200 и неизменные SHA-256
agent/evidence/RAG. Код приложения и промпт обеих моделей одинаковы во всех
12 запусках; совпадение проверено manifest и prompt hash.

| Вопрос / профиль | Три полных времени, с | Медиана, с | Диапазон, с | Содержательных ответов | Полнота по рубрике |
|---|---|---:|---|---:|---|
| HS / mini | 8,87; 8,42; 10,87 | 8,87 | 8,42–10,87 | 2/3 | 4/4; 2/4; 0/4 |
| HS / Luna medium | 43,87; 27,05; 16,81 | 27,05 | 16,81–43,87 | 3/3 | 4/4; 4/4; 4/4 |
| Границы / mini | 6,92; 8,21; 6,79 | 6,92 | 6,79–8,21 | 3/3 | категории 3/3 во всех; ошибка области во всех |
| Границы / Luna medium | 62,78 отказ; 14,27; 14,45 | 14,45 | 14,27–62,78 | 2/3 | 0/3; 3/3; 3/3 |

«Содержательный» означает, что дан обзор, а не отказ; это **не синоним
правильного ответа**. Mini дала 5/6 обзоров, из них четыре имеют существенную
ошибку области/grounding; Luna дала 5/6 обзоров без обнаруженных существенных
фактических ошибок, с одной оговоркой по обрезанному фрагменту цитаты ниже.
Полнота — наличие заданных аспектов, точность проверяется отдельно:
упоминание категории не компенсирует ошибку её интерпретации.

Если отдельно считать только содержательные ответы, медиана HS mini —
8,64 с (n=2), Luna — 27,05 с (n=3); границы mini — 6,92 с (n=3),
Luna — 14,36 с (n=2). Основная таблица сохраняет все исходы и не прячет отказы.

Mini всегда прекращала поиск после одного вызова. Это уменьшило задержку,
но один раз оставило нерелевантную выдачу без исправления. Luna для HS
использовала 3/3/2 поиска; обзоры получились устойчивее, но дольше.
На двух содержательных ответах о границах обе модели использовали один поиск,
а model time Luna составляло 11,39–12,36 с против mini 3,84–4,77 с.
Значит, разница сохраняется и при одинаковом числе поисков; её нельзя целиком
отнести к прежней медленной CHM-подготовке.

Slot 2 получил готовый безопасный ответ после unavailable, а не исключение
верхнего уровня. Первоначальный wrapper измерял только успешный retrieval;
его длительность/причина не сохранены. Остаток total minus model — 31,16 с,
но это не точный замер retrieval и не доказательство сетевого таймаута.
После этого instrumentation добавляет duration/error class и для исключений;
это не меняет приложение, inputs или поведение поиска. Сбой не повторился.
Повторных API-попыток не было: ровно 12 запусков, 12 финальных ответов,
из них два без содержательного обзора. Они не заменялись удобными повторами.

## Usage и воспроизведение

| Профиль, 6 ответов | Input | Output, включая reasoning | Reasoning внутри output | Cached read | Cache creation |
|---|---:|---:|---:|---:|---:|
| mini | 53 464 | 2 459 | 0 | 24 960 | 0 reported |
| Luna medium | 99 123 | 4 734 | 1 944 | 63 106 | 35 966 |

Это usage только вызовов агента, без embeddings и вспомогательных сервисов;
нулевое cache creation у mini означает поле отсутствует/не сообщено через
Chat Completions, а не доказательство отсутствия кеширования. Reasoning второй
раз к output не прибавляется. Стоимость не рассчитывалась. Exact profile:
history window 10, общий context budget 118 808 для обеих моделей,
brief target 500, caps 500/8692, max retries 0, одинаковый timeout из production.

Runner: [compare_optimized_models.py](../scripts/compare_optimized_models.py).
Метрики/ручные findings/manifest: [summary.json](../tests/eval/results/2026-10-15_optimized_model_ab/summary.json).
Private artifacts: `var/optimized_model_ab/manifest.json`, `sample_00.json`…
`sample_11.json`, `attempt_*.json`; входы `var/latency_inputs_real.json`.
Runner выполнялся через `docker exec` в существующем app, каждый slot —
новый процесс с InMemorySaver и запрещённым send adapter. Настройки модели
передаются копией settings только этому процессу. Пример после разрешения API:
`python /app/var/compare_optimized_models.py 0`; успешный slot повторно не
запускается. Для нового эксперимента требуется отдельный каталог/manifest.

Проверки: runner `py_compile`, Ruff и `git diff --check` — PASS; проверены
12 результатов, одинаковый prompt hash, допустимые citation indexes,
соответствие citation evidence и runtime hashes. Нового полного pytest нет:
приложение в этом эксперименте не изменялось. Предыдущие тесты оптимизации
сохранены в её отдельном отчёте. Секреты и полные тексты диалога в Git не
добавлялись; commit/push не выполнялись.

Ограничения: два заранее известных вопроса, три повтора, живой поиск с разными
model-generated queries, разные API/reasoning/caps, shared filesystem и
provider cache, заметный jitter. Это сравнение практических профилей на одном
итоговом коде, не статистическое доказательство превосходства моделей и не
SLA. Рекомендация в пользу Luna обусловлена наблюдаемой точностью, несмотря
на её более высокую задержку и один отказ retrieval.
