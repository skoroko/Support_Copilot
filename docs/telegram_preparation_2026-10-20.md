# Ускорение подготовки ответа — 20 октября 2026

Основа: `461daff` / PR49. Runtime — `gpt-6-luna`, Responses, medium. Модель,
reasoning, потолки output, grounding, moderation и approval сохранены. Первичный
evidence budget12К, прицельное дополнение6К; аварийные ограничения60/90/105с.
Обновление не требует миграций, изменения корпуса или переиндексации.

## Что изменено

- Независимые read-only tool searches выполняются параллельно, результаты
  объединяются в прежнем порядке. Один batch разделяет предел двух dense
  workers. Смешанные actions сохраняют последовательность и human approval.
- Исходный recall запускается сразу; перевод не задерживает его начало.
  Translation/embedding clients переиспользуют соединения, учитывают остаток
  общего времени и закрываются владельцем. Mutable BM25 metadata копируется
  для отдельного вызова; workers закрываются до завершения accounting.
- Первый evidence packet остаётся неизменным префиксом model input. Последующие
  tool results дописывают полные актуальные записи цитат и ограничения; последняя
  запись citation_number имеет приоритет. Checkpoint хранит cumulative evidence.
  При переполнении контекста используется прежнее cumulative-представление,
  без удаления текущих фактов или повышения token budget. JSON уплотнён без
  потери полей. В наблюдении v11 cache-read вырос1500→8445→15873 токенов,
  почти до полного предыдущего input8448→15876; это не гарантия cache hit.
- Один source_id/hash даёт одинаковую citation identity при direct/related
  retrieval, даже если legacy document_id различается. Exact duplicate больше
  не занимает место второй цитатой, вытесняя ещё не переданные определения.
- Выбранный native span короткой PDF-страницы можно дополнить непрерывными
  соседними определениями только в свободное место. Короткий CHM/HTML member
  допускает дочитывание полного непрерывного текстового префикса от opening span
  до первого изображения/неподходящего блока; только если весь префикс помещается.
  Ссылки не обходятся, содержание изображений не интерпретируется. Проверяются bytes/hash,
  source/location, полный span, порядок, отсутствие пропущенных непустых блоков
  и review status. Старые тексты, слоты, ranking и общий размер не меняются.
  Это буквальная co-location, не утверждение семантической связи. Raw API
  сохраняет каждый block/text/bbox/quality flag; модель получает весь текст
  и индивидуальные quality flags без дублирования геометрии.
- В `compose.luna.yaml`: через6с медленного brief invoke допускается идентичная
  резервная генерация. Максимум два дополнительных запроса за весь turn,
  один одновременно на приложение, без очереди. Первый полный результат
  побеждает; частичный/invalid результат победить не может. Проигравший stream
  отменяется и дожидается закрытия. Только выбранные tool calls исполняются.
  Expanded и direct agent stream не дублируются; общий default0 — выключено.
- Последний из прежних шести model turns просит окончательный grounded ответ
  по найденным данным, вместо запроса инструмента, который уже нельзя выполнить.
  Для вопроса о моделировании взаимодействия требуется объяснить управляющие
  параметры; общие слова о назначении не заменяют объяснение механизма.

## Измерения и качество

Использованы только пять публичных вопросов `tests/eval/verification_set.json`.
Каждый получает fresh in-memory graph. Telegram send запрещён тестовым адаптером;
production history/checkpoints не изменяются. Замер — до полного grounded
ответа, без cold startup и реальной Telegram доставки. Последовательные
нерандомизированные cohorts зависят от очередей провайдера и prompt cache.
Это не P95, доказательство причинности всех дельт или общий SLA.

Все пять v16 завершены с источниками. Самый проблемный DOF стал полнее:
раньше1–4 не подтверждались, теперь все шесть соответствий присутствуют в

В v16 Kn/Kt подтверждены прямым дополнительным поиском; стоимость этой полноты
видна в числе шагов и времени. Механическая проверка номеров цитат не является
смысловой оценкой: ответы отдельно сопоставлены с evidence и baseline.

Все эти попытки завершены ответами, однако проверка номеров цитат не доказывает
качество. В v17 условие нулевого избыточного порового давления для дренирования
потерялось при18К cumulative cap. В v18/v19/v20 тело этого раздела не попало в
найденные тексты; v19/v20 также пропустили видимое условие Transmitting boundary.
В v20 ограничение модели Мора–Кулона было привязано к цитате Interface,
которая его не подтверждает, хотя факт есть в другом сохранённом источнике.
Новый literal prefix в retrieval32 не сработал: соответствующий member вообще
не был выбран, поэтому польза этого fallback именно для32 live-прогоном не доказана.

Agent-first v19/v20 дал меньший разброс времени, но проверку отсутствия потерь
относительно baseline не прошёл. В production-профиль он не переносится:
`AGENT_PREPARED_EVIDENCE_ENABLED` сохраняет прежнее значение true. Медиана v20
18.81с против16.49с контроля также не доказывает общего ускорения. Безусловное
сохранение качества каждого ответа и стабильные10–15с пока не достигнуты.

## Отклонённые варианты и практические границы

Все доступные cohorts, ошибки, iteration failures, usages и ограничения:
[машинный отчёт](telegram_preparation_2026-10-20.json). v2_after прерван после
первого вопроса. Первый v12 прерван после четырёх для добавления защиты порядка;
его label случайно переиспользован, raw answers утрачены. Доступные stdout
timings явно сохранены отдельно и исключены из итогового сравнения.

Увеличение packet до24К не устранило provider timeouts. Один backup на весь
turn оставлял следующий медленный invoke без защиты. Старый agent-first путь
сохранил iteration-limit failure. Batch-search prompt дал смысловые потери;
общее усиление требований ко всем моделям увеличило поиски до37–43с. Эти
варианты не используются. Финальный профиль не является полным откатом.

Провайдер отдавал первый chunk раньше секунды, но полный ответ через49–60с.
Это подтверждает наличие задержки после начала provider stream; оно не позволяет
разделить очередь, inference и сетевую доставку. Streaming/buffered ABBA-пилот
также не установил причинность: одна stream попытка timed out, остальные три
завершились за8–11с. Простое уменьшение timeout ускорением не считается.

Резервный вызов может повысить API-расход. Для проигравшего отменённого запроса
usage часто неизвестен и может тарифицироваться; он не записывается как ноль.
Известные usages обеих завершившихся попыток сохраняются отдельно от winner.
Точную экономию/переплату по одному winner usage утверждать нельзя.

Часть контрольных вопросов стала медленнее. Финальный профиль сокращает
повторную подготовку и защищает от одиночного длинного provider tail, но не
гарантирует каждый ответ за10–15с или отсутствие всех внешних ошибок. Общий
release gate S0-005 остаётся открытым; маленький набор не заменяет holdout.
