# Инвентаризация RAG-корпуса

Повторная read-only проверка 16 октября 2026 года подтверждает 70 исходных файлов
двух требуемых форматов плюс исходный CHM: PDF — 9, HTML — 60, CHM — 1;
общий размер индексируемого корпуса — 82 110 308 байт (78.31 MiB). Файл
`data/support_documents.json` — результат предыдущего упражнения, а не
исходный документ для файлового RAG, поэтому в счётчик корпуса не входит.

Для Б5.5 выполнена детерминированная офлайн-подготовка 60 реальных страниц
из уже входящей в корпус справки `GTS_NX 2021.chm`. Скрипт не ходит в сеть и
не генерирует факты: он извлекает текст CHMReader, HTML-экранирует его и
сохраняет в `data/gts_nx_help_html/` с предсказуемыми именами.

```powershell
python scripts/download_data.py --from-chm "data/rag-block-03/GTS_NX 2021.chm" --output-dir data/gts_nx_help_html --limit 60
```

Фактическая структура после запуска:

| Каталог | Форматы | Число файлов | Размер, байт |
|---|---|---:|---:|
| `data/rag-block-03` | PDF — 9, CHM — 1 | 10 | 81 730 905 |
| `data/gts_nx_help_html` | HTML — 60 | 60 | 379 403 |
| **Исходный RAG-корпус** | PDF, HTML, CHM | **70** | **82 110 308** |

Это превышает требование 30 реальных документов (и checkpoint 50+), а также
даёт два требуемых формата — PDF и HTML. Каталог `gts_nx_help_html` — производное
зеркало членов того же `GTS_NX 2021.chm` и исключён из ingestion через
`RAG_INGEST_EXCLUDE_DIRS` (дедупликация HTML/CHM-членов); файлы остаются на диске
как артефакт формата HTML.

Для альтернативных, предварительно проверенных источников тот же скрипт
принимает JSON-манифест. Этот режим требует `--allow-download`; без флага
сетевой запрос не выполняется.

## Покрытие и пробелы корпуса

Продуктовая разметка (`product` в payload чанков) выводится по маркерам в
имени файла и пути внутри каталога корпуса; родительские каталоги окружения
не учитываются. Нейтральные имена наследуют `RAG_PRODUCT`:

- `gts_nx` — основной массив: 8 PDF глав User Manual / Пособия по расчётам,
  `GTS_NX 2021.chm` и 60 извлечённых из него HTML-разделов. Английские главы
  `NN_User Manual_ChapterK_*.pdf` маркеров не содержат и помечены `gts_nx`
  через дефолт.
- `civil` — «Руководство по расчетам midas Civil 2020.pdf», единственный
  явно помеченный не-GTS документ корпуса.

Отдельные внутренние материалы, пока не добавленные в корпус:

- установка, лицензирование и активация продуктов MIDAS;
- собственный каталог обращений, решений и эскалаций поддержки;
- внутренняя база знаний / FAQ поддержки;
- руководства других продуктов (midas Gen, FEA NX, SoilWorks, NFX и т.д.).

В CHM уже есть 119 разделов Troubleshooting, включая ERROR1046, ERROR2111,
ERROR2138 и Warning4016/4045. Отсутствие отдельного внутреннего каталога не
означает отсутствие документированных ошибок производителя. Каждый вопрос
проверяется по источникам, а не отклоняется по этому списку.

## Сверка извлечения и рабочего индекса 16.10.2026

У девяти PDF суммарно 1440 физических страниц. Старый docstore содержит 1438;
две отсутствующие страницы Civil (2 и 128) просмотрены и визуально пусты.
В CHM 496 HTML-членов, старый docstore содержит 494. Два пропуска — копии
PM4Sand с кириллицей в имени. Причина исправлена в reader: точные members
извлекаются в ASCII output path с проверкой размера. Новый каталог содержит
все 496 тем без ошибки чтения; рабочий индекс ещё не обновлялся.
Все 60 отдельных HTML — текстовые производные
этой справки; исходная разметка таблиц, ссылки и рисунки в них утрачены.

Активный docstore содержит 1992 документа: PDF 1438, CHM 494, HTML 60.
Read-only snapshot коллекции Qdrant `rag_eval_chunk_1024` содержит 2356
фрагментов: PDF 1482, CHM 757, HTML 117. Это разные единицы учёта.
У 701 документа старого docstore ошибочный product `projects`; новые правила
разметки уже исправлены, но старую коллекцию они автоматически не меняют.
Хешей исходников и полного provenance у старых записей нет: совпадение
численности не подтверждает актуальность или смысловую полноту индекса.

На смешанных страницах подтверждены невосстановленные визуальные данные:
формула 4.1.4 и обозначения в «Материалы», с. 3; формулы 5.4.10–13 в
«Алгоритмы», с. 15; таблица X/Y/Z на скриншоте Mesh, с. 150. Номера здесь
физические. Новый каталог сохраняет координаты и хеши этих областей; их
содержимое требует проверенной транскрипции, а не догадки по подписи.
Методика и точные артефакты — [documentation_evidence.md](documentation_evidence.md).

**Решение (2026-09-23):** текущая версия агента работает только с мануалами;
пополнение по этим направлениям запланировано на следующую версию агента.
Этот список — чек-лист для того инкремента.

`data/support_documents.json` — синтетический набор из прошлого упражнения
(шаблонные тексты, не факты MIDAS); в индексируемый корпус его не включать.

Как пополнять: файл кладётся в `data/<category>/`, `product` определяется
маркерами в имени/пути (`midas Civil`, `FEA NX`, `SoilWorks`, `midas <имя>`)
или наследует `RAG_PRODUCT`; форматы — pdf, docx, html, md, txt, chm.
Переиндексация инкрементальная (UPSERT по docstore). При
`RAG_PRODUCT_SCOPE=fallback` новые продукты становятся достижимыми сразу;
`RAG_PRODUCT_SCOPE=all` отвечает по всему корпусу без приоритета GTS NX.
