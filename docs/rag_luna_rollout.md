## Действующая конфигурация

```dotenv
RAG_LLM_MODEL=gpt-6-luna
RAG_REASONING_EFFORT=medium
RAG_CONDENSE_REASONING_EFFORT=none
```

Уже реализованный адаптер использует Responses API с `store=false` для
генерации, streaming и переформулирования. Код генерации в этом переключении
не менялся. `compose.luna.yaml` не переопределяет RAG-параметры; они берутся
из `.env`. Для применения последующих изменений конфигурации:

```powershell
docker compose -f compose.yaml -f compose.luna.yaml up -d --no-deps app
```

Telegram-агент сохраняет Luna medium для обычных и расширенных ответов.
`OPENAI_MODEL` для прежнего CLI не изменён.

## Проверка работающего backend

Проверки выполнены через настоящий HTTP backend, OpenAI API, Qdrant и
PostgreSQL с изолированными eval-профилями. Сообщения в Telegram не отправлялись.

| Сценарий | Результат | Время, с |
|---|---|---:|
| Степени свободы в цилиндрических координатах | HTTP 200, ответ и 2 источника | 9.77 |
| Алгоритмы нелинейного расчёта | HTTP 200, ответ и 2 источника | 8.22 |
| Уточнение с историей диалога | HTTP 200, ответ и 1 источник | 9.00 |
| SLA по неизвестному договору | HTTP 200, штатный отказ без выдуманных сроков и источников | 3.64 |
| Переформулирование уточнения, `/rag/retrieve` | HTTP 200, `plan_mode=condense_hook`, 5 источников | 10.00 |
| Потоковый RAG-ответ через web chat API | SSE завершён, ответ и 1 источник сохранены | 15.15 |
| Регрессия Telegram-агента через backend | SSE завершён, ответ и 1 источник сохранены | 12.55 |

Номера цитат корректны во всех ответах с источниками. В обоих потоковых
сценариях текст и источники совпадают с сохранённой историей. Время включает
поиск и обращения к провайдеру; это функциональная проверка переключения,
а не сравнительный benchmark качества или производительности.

При подготовке smoke-проверки исправлены две ошибки самого проверочного
скрипта: поле `question` в `/rag/retrieve` по контракту сохраняет исходный
вопрос, а Telegram-клиент по умолчанию отправляет заголовки интерфейса
`telegram`. Для web-проверки заголовки согласованы на всех запросах.
Переформулирование подтверждено по телеметрии: `condense_hook` означает
успешный LLM rewrite, отличающийся от исходного вопроса. Первые пять
успешных запросов повторно не выполнялись; исходные результаты сохранены.
