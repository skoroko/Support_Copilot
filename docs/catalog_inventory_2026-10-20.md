Основа: main `df96941` / PR51. Задача — ускорить подготовку ответа о доступных
моделях, сохранив качество, модель и глубину reasoning. Полная переиндексация

## Исторический пилот v1/v2

`RAG_CATALOG_INVENTORY_ENABLED` по умолчанию выключен. Для явных RU/EN вопросов
о перечне отдельный BM25 ищет целую DOM-таблицу до финального ограничения
обычных chunks. Вопросы о процедуре, сравнении и определении идут прежним путём.
Нет реестра моделей грунта или других предметных подсказок в коде.

Дополнение допускается только после прежнего положительного dense confidence,
при точном совпадении продукта/версии и достаточном буквальном совпадении
предмета с заголовочными полями таблицы. Значения отдельных строк не считаются
заголовочными anchors. Неизвестный продукт исключается; неизвестная версия
сохраняется явно. Конфликтующие близкие каталоги отклоняются.

Проверяются текущий SHA исходника, source/location binding, parent_table,
последовательность строк, уникальность origins, rowspan/colspan и literal
resolved grid. Первая строка не объявляется семантически проверенным заголовком.
PDF-таблицы с неподтверждённой структурой не используются этим маршрутом.
Механическая проверка не доказывает инженерную корректность или полноту каталога.

Целая таблица получает собственный стабильный citation identity, score0 и
отдельный локатор. Все ordered block IDs, source hash и текстовый SHA сохранены;
полные cell attributes доступны в связанном каталоге. Таблица резервируется
атомарно внутри прежних12К, максимум6К/половина доступного бюджета; обычные
источники остаются. Общий предел12К+6К не увеличен. При OFF распределение
обычного контекста совпадает с прежним.

Кэш строится до readiness, один раз на снимок каталога. Обновление каталога
инвалидирует представление; изменение источника запрещает устаревшую таблицу.
В принятом корпусе механическую проверку проходят97 DOM-групп. Material.htm
содержит31 строку, включая буквальные названия колонок; целый текст5008символов.
Повторные lookup в отдельной микропробе занимали0,02–0,06с; это не время ответа.

## Ограничения

Таблица занимает часть прежнего бюджета и одно место обычного seed; это
согласованный tradeoff, требующий проверки ответов. Консервативные anchors могут
пропустить подходящий каталог. Нет утверждения о полном списке для всех версий
GTS NX или придуманной связи каталога с подробными страницами. Дополнительные
модели из других обоснованных источников нельзя отбрасывать только из-за
отсутствия в таблице неизвестной версии.

Модель, reasoning, Fast2×, grounding, approval и сроки ожидания не меняются.
Decisions API не включается: локальная проверка операции не требует ещё одного
модельного запроса. Общие критерии качества и10–15с для всех ответов S0-005
остаются открытыми до отдельных доказательств.

## Доработка PR52: архитектурное решение

Текущий кандидат добавляет request-scoped lexical memo, пакетное распределение
новых доказательств без удаления уже видимого текста, полные небольшие физические
страницы отдельной квотой до 6К при пакете18К или до12К при явном пакете24К,
после прежнего пакета12К, и буквальную навигацию по
проверенным PDF-источникам и буквальным заголовкам CHM-разделов в точной общей
директории двух разных проверенных members. Модель может прочитать 1–3 страницы/раздела точно по выданным
сервером ID. Подсказки навигации не цитируются. Проверки bytes/hash, продукта,
версии, страницы и локатора выполняются повторно при чтении.

Семантический selector `off|responses|decisions` используется только если
буквальные anchors таблицы не совпали. Он выбирает из механически проверенных
DOM-таблиц нужной product/version partition; возвращённый ID и источник
проверяются заново. Подтверждённый strict lexical seed допускается наравне с
dense seed, как и в прежнем confidence gate. Score добавлений остаётся0;
они не превращают слабый поиск в доказанный ответ. Начальная/дополнительная
квоты конфигурируемы, прежние defaults 12К/6К сохранены.

Ответственный модуль для provenance, snapshot invalidation и whole-unit
чтения — `RelatedEvidenceIndex`. **Keep:** общий resolver/lock/source-hash cache
сохраняются в одном месте, чтобы разные пути не расходились по доверенным bytes.
**Split:** HTTP transport и строгие контракты selector/auditor вынесены в
самостоятельные модули, а allocation/projection — в `prepared_evidence`.
`RAGService` координирует выбор и бюджет; graph координирует состояние и stable
citations, без файлового чтения или HTTP transport внутри model node.
**Defer:** разделение legacy `rag.py` (>1500 SLOC) и graph по произвольным строковым
порогам не включено: оно увеличило бы риск изменения ранжирования/истории в
этом исправлении. Следующая архитектурная граница для выделения — общий context
selection/packaging, при сохранении сравнительных тестов прежнего пакета 12К.
Это осознанное исключение размера для этого PR, не отмена quality policy.

Исключение к правилу роста legacy-файлов: владелец **skoroko / maintainer**,
задача **S0-005**, повторное архитектурное review **2026-10-27** или раньше при
следующем изменении selection/packaging. Метрика — строки с Python-токенами
(без пустых строк и комментариев), `origin/main` → текущий кандидат:

| Путь | До | После | Решение и граница |
|---|---:|---:|---|
| `app/services/rag.py` | 2434 | 2582 | defer выделения selection/packaging; сохранить прежние confidence gates и пакет12К |
| `app/services/agent_persistent.py` | 1028 | 1180 | keep graph state/citation lifecycle; transport вынесен |
| `app/services/related_evidence.py` | 293 | 854 | keep source/hash/lock lifecycle; физические и структурные locators не смешиваются с semantic relations |

Риск немедленного разделения — разные правила invalidation и нумерации цитат
в параллельных путях. Связность проверяют `test_physical_contexts`,
`test_location_context_rag`, `test_navigation_evidence`, `test_chm_navigation`,
`test_agent_navigation`, `test_search_batch_allocation` и expansion contracts.
Следующий review должен переоценить выделение чистого selection/packaging;
исключение не разрешает добавлять в эти файлы независимый transport/UI/persistence.

Физические группы собираются одним синхронным batch: текущие пути и stamps
каталога/каждого источника проверяются в начале и конце. Изменение инвалидирует
весь batch; проверка не кэшируется между запросами. PDF navigation сохраняет
предел100/10К с явным `truncated`: полного manifest всех страниц не обещает.

Окончательный runtime gate остаётся отдельным от unit/review. Промежуточные
cohorts и неудачные варианты сохраняются; отсутствие исключения или наличие
ссылок само по себе не считается подтверждением полноты.
