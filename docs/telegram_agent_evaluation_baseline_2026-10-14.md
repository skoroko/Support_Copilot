# Baseline Telegram-агента до исправления цитат — 14 октября 2026

Этот отчёт сохраняет первоначальный прогон `87dad8a9d1b245e382ce5c1dbd98655c`.
Исходные JSON/CSV остались неизменными в `2026-10-14_telegram_agent`.
Результаты исправленной версии приведены в
[актуальном сравнении](telegram_agent_evaluation.md); числа ниже относятся
только к baseline.

**Новый живой прогон выполнен через текущий Telegram-контур. Главный выявленный
дефект — смысловое несоответствие части цитат.** Получено 33 из 34 эталонных
ответов; 25 имеют полную оценку правильности/полноты. Среди 32 полученных
технических ответов только 14 полностью подтверждаются именно указанными
фрагментами. Корректные отказы и механизм подтверждённого расширения работают
на проверенных сценариях. Называть качество цитирования достаточным для
финальной сдачи по этому прогону нельзя.

Это отдельная оценка от [экспериментов RAG за сентябрь](rag_evaluation.md).
Сентябрьские RAGAS, модели судьи и сравнения chunking не перенесены в новые
показатели и не используются как оценка агентного контура.

## Наборы и методика

[Golden dataset](../tests/eval/golden_dataset.json) сохранён без изменений:
**34 вопроса**, включая один отказ по стоимости лицензии. Дополнительно
использованы document/page-предикаты из
[retrieval dataset](../tests/eval/retrieval_dataset.json). Наборы сопоставлены
по нормализованному вопросу, а не вслепую по номеру. Единственное намеренное
сопоставление по индексу — №34: явный вопрос о плоской деформации и его
контекстный вариант имеют один целевой факт. История из retrieval dataset
в эталонные вопросы не подставлялась. №31 в двух наборах сформулирован
по-разному: его source-прокси не считались, смысл ответа проверен отдельно.

Дополнительный набор — **9 ходов**: три пары «начальный вопрос → уточнение»,
один вопрос без контекста и два отказа по отсутствующим коммерческим/договорным
сведениям. Подробный режим отдельно проверен на №1, 10, 16, 24 и 32.
Всего сохранены **43 запроса и 5 подтверждённых расширений, 48 оценок**.

Ответ и sources читаются до конца SSE, включая sources после `done`, и
сверяются с каноническим сохранённым сообщением. В 42 завершённых обычных
запросах транспорт и сохранённый ответ/источники совпали. Ошибка №17 не
повторялась и не заменялась удачным ответом. Для проверки доказательств
прочитаны **40 контрольных точек**, без пропусков и без повторного retrieval.

Правильность/полнота и смысл цитат оценены качественным разбором Codex с двумя
пакетами проверки GPT-6.1 Sol High. Это **не RAGAS, не независимая слепая
экспертная оценка и не статистически калиброванная accuracy**. Один живой
прогон не показывает разброс модели и сети. Для каждого ответа сохранены
балл и конкретное основание в `semantic_review.json` и `answers.csv`.

Шкала правильности/полноты: **1** — существенные положения эталона верны и
раскрыты; **0.5** — существенный пропуск относительно эталона либо небольшая
фактическая ошибка; **0** — неверное ядро ответа или ответ не получен.
Половинный балл не обязательно означает ложный факт.

Шкала подтверждения цитатами: **1** — существенные утверждения подтверждены
именно указанными фрагментами; **0.5** — небольшая неподтверждённая деталь или
неточная атрибуция; **0** — существенное несоответствие утверждения и источника.
Для отказов, уточнения условий и транспортной ошибки эта шкала неприменима.
Финальная ссылка `[N]` сопоставляется с `sources[N-1]`, затем по `chunk_id` с
исходным tool-контекстом; сырая нумерация до финального перенумерования не
используется вместо итоговой.

## Разбор и следующие исправления

1. **Атрибуция фактов.** №1 ссылается на Algorithms PDF52/331 о волнах
   свободного поля; нужный Node PDF3/10 был найден. №14 о PM4Sand ссылается
   на HTML nonlinear time history + SRM вместо Materials PDF87/216.
   Нужна проверка соответствия claim → финальный chunk, включая перенумерование
   и объединение результатов поисков. Причина ошибочного выбора пока не доказана.
2. **Соседние модели материалов.** №10/11 смешивают ссылки на классическую и
   Modified Mohr–Coulomb; уточнение добавляет неподтверждённую рекомендацию.
   Простое наличие ключевых слов или документа Materials не обнаруживает дефект.
3. **Полнота.** №3 не раскрывает геометрическое отличие систем; №15 пропускает
   часть параметров ненасыщенной среды; №26 не объясняет отношение напряжений
   через K0; №27 пропускает Embed. Рубрика сохраняет эти пропуски отдельно
   от транспортных ошибок и ошибок цитирования.
4. **Подробный режим.** Требуется проверять новые утверждения и полезность
   раскрытия, а не длину. №32 — положительный пример; №1 — повторение, №24 —
   усиление не подтверждённого указанными фрагментами объяснения.
5. **Надёжность.** Диагностировать ошибку потока №17 и повторить полный
   независимый прогон после исправления, сохранив текущий как baseline.

Дополнительные ограничения эталона: причинное объяснение в reference №13
сильнее найденных доказательств; его отсутствие не штрафовалось. Подробный
№32 повторяет подозрительное описание x/y-закреплений нижней границы из самого
мануала; это требует предметной проверки корпуса, а не считается выдумкой модели.
Корпус не пополнялся.

Новый живой прогон с действующей конфигурацией и разрешённой передачей
вопросов/фрагментов провайдеру:

```powershell
.venv/Scripts/python.exe -X utf8 scripts/evaluate_telegram_agent.py --api-url http://127.0.0.1:18000 --output var/telegram-evaluation-new.json --allow-external-data-transfer
```

Для smoke доступен `--limit 2`; для отдельного набора без expanded —
`--no-expansions`. Без разрешающего флага внешние вызовы запрещены.
`--resume-safe` пропускает любой уже сохранённый запрос, включая ошибочный
или прерванный: потерянный ответ не запускает второй платный вызов.
Это продолжение незапущенных сценариев, не автоматическое исправление ошибок.
Снимок версии для следующего прогона нужно снять заново; старый manifest
нельзя использовать как доказательство неизменности нового deployment.

Экспорт checkpoint выполняется в том же deployment с доступом к его saver:

```powershell

docker cp tests/eval/results/2026-10-14_telegram_agent/run.json helpdesk_assistant-app-1:/tmp/telegram_eval_run.json
docker exec helpdesk_assistant-app-1 python /tmp/export_agent_eval_evidence.py --run /tmp/telegram_eval_run.json --output /app/var/telegram_eval_checkpoints.json
```
