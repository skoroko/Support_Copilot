# GPT-6 Luna: eval Support Copilot, 15.10.2026

## Решение

Для пилота выбран **gpt-6-luna medium** и для обычного ответа, и для Подробнее. На fixed-наборе полнота равна mini (0.906), а expanded получает 0.900/1.000 по полноте/grounding против 0.800/0.800 у mini. На live-наборе medium — 0.906/1.000, генерация $0.01456 за 16 ответов против $0.08724 у mini (примерно в 6 раз дешевле), медиана 12.41 с против 9.66 с.

Low — вариант при приоритете задержки и цены: live 7.88 с, $0.01034, но полнота 0.844. High и xhigh не выбраны по умолчанию: live-полнота выше, но у high grounding 0.846; xhigh медленнее (20.58 с) и не выигрывает fixed-набор. None имеет больше ошибок цитирования на fixed. Это выбор кандидата для пилота, а не доказательство общей не меньшей точности.

15.10.2026 по отдельному запросу пользователя профиль `compose.luna.yaml` активирован: backend бота использует Luna medium для обычных и расширенных ответов. Выбор сохранён также в локальном `.env`. [Отчёт о переключении и проверке](luna_runtime_rollout.md). RAG API сохраняет отдельную настройку `RAG_LLM_MODEL`; corpus/embeddings не меняются. Старые tool-free API используют none.

Для production-замены: 20 новых обращений с независимыми эталонами, 3 повтора mini и Luna medium, обязательная проверка инженером ошибок цитат и технических гарантий. Зафиксировать приемлемую задержку и допустимую разницу полноты до прогона. Имеющиеся bootstrap-интервалы включают ноль.

## Реализация и проверка

Responses API для GPT-6, настройка reasoning отдельно для brief/expanded, store=false, encrypted reasoning для tool loop, корректная обработка incomplete и usage. RAG обходит устаревший реестр LlamaIndex и поддерживает Responses streaming. В cache legacy API включена разрешённая default model, чтобы смена модели не использовала старый ответ.

Полный pytest: 843 passed, 11 skipped. После дополнений конфигурации/streaming: 198 passed; проверка адаптера/eval accounting/fingerprint: 21 passed. Ruff адаптера, config, graph, новых скриптов/тестов и git diff --check проходят. В старых RAG/legacy файлах сохраняются 16 прежних Ruff замечаний (сверены с исходным checkout). Зависимости: OpenAI 2.54.0, LangChain OpenAI 1.6.2, Python 3.13.

Выборочно просмотрены ответы по координатам, Мору-Кулону и нелинейному решателю: например, low ошибочно превращает произвольную ориентацию координат в третий тип; medium на неполной выдаче явно ограничивает подтверждённый перечень решателей. Общая оценка остаётся модельной; отметка Sol critical для сообщения о лимите итераций ошибочно классифицирует технический сбой как неподтверждённый факт и не используется как подтверждённая экспертная находка.

## Как читать результаты

Верность/полнота и grounding — средние оценки слепого GPT-6.1 Sol low по шкале 0 / 0.5 / 1, **не доля правильных ответов и не независимая человеческая экспертиза**. Grounding оценивается по конкретным процитированным фрагментам; чистые отказы/уточнения имеют null и исключаются из его знаменателя. Низкая полнота учитывает необоснованные отказы. Метки моделей скрыты, порядок перемешан детерминированно. Исходные заметки оценщика сохранены; его critical flags требуют проверки инженером.

Фрагменты первой части fixed-оценки одинаковы между вариантами (проверено по SHA-256); для второй части и live каждая цитата дополнительно привязана к хешу конкретного текста. История follow-up строится из ответов самого кандидата. Fixed retrieval возвращает ту же выдачу при повторном поиске: это не проверка качества поисковых запросов. Один xhigh fixed-сценарий достиг лимита итераций; это считается потерей полезности, а не сетевой ошибкой.

Лимиты mini/Luna none — 500/1500; при reasoning общий max_output_tokens — 8692/9692. Отдельного жёсткого лимита видимого ответа API не даёт. Краткость задаётся одинаковой инструкцией 3–5 пунктов. Стоимость рассчитана по usage, включая cache read/write; output уже включает reasoning, второй раз он не прибавляется. Live-стоимость включает генерацию агента, исключает query embeddings и вспомогательный condense. Задержка — до полного ответа, **не TTFT**; concurrency=3, единичный прогон, сеть и cache влияют на время. Luna none fixed повторена после ошибки Windows при сохранении артефакта; исходная попытка сохранена отдельно.

Набор небольшой и ранее использовался при настройке промптов. Доверительные интервалы парных различий полноты (bootstrap по разговорам, 10 000 выборок) сохранены в summary.json; они не подтверждают устойчивое превосходство Luna над mini. Для production-замены нужен отдельный набор новых обращений и повторения.
