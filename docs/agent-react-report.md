# ДЗ 6.2 — сравнение наивного и ReAct-агентов

ReAct-инкремент реализован на нативном OpenAI Chat Completions API: один
разрешённый tool на итерацию, затем независимый critic-вызов.  Основная модель
по умолчанию — `gpt-5.4-mini`; при `--premium-after-revision` следующий шаг
после замечания критика может использовать `gpt-5.4`.  Значения model id
сверялись с официальными каталогом моделей и руководством OpenAI по function
calling перед реализацией.

Live-сравнение выполнено 14 сентября 2026 года: каждый из пяти кейсов один раз
прогнан на `agent_naive.py` и один раз на `agent_react.py`. Результаты и полные
trace сохранены в `docs/agent-comparison-results/`. Кейс 4 был повторён после
исправления Unicode-кодировки изолированного tool-процесса; в таблице указано
значение успешного контрольного прогона.

## Наблюдения

1. Reflection помог в кейсе 3: naive выдал инструкции для ошибки расчёта после
   обновления как ответ про лицензионную ошибку. Critic дважды отметил
   несоответствие, после чего ReAct не стал выдумывать процедуру и предложил
   проверку или эскалацию.
2. На простых кейсах critic отвечал `OK` и не улучшал результат, но увеличил
   расход: 1 726 против 1 072 токенов в кейсе 1 и 1 421 против 873 в кейсе 2.
3. ReAct оказался корректнее в одном из пяти кейсов, однако общий расход вырос
   с 5 823 до 10 989 токенов, а число шагов — с 11 до 12. Для типовых запросов
   reflection следует включать осознанно, а не считать бесплатным улучшением.
4. Ожидание, что naive обязательно вызовет tool на провокации, не подтвердилось:
   оба агента корректно отказались от prompt injection за один шаг и без tools.
5. Ни один live-прогон не ушёл в runaway-цикл. Отдельные offline-тесты при этом
   подтверждают точные ответы `Timeout` и `Превышен лимит итераций`, а также
   общий предел в две применённые ревизии.

## Что сравнивается

- Наивный агент из ДЗ 6.1 делает tool loop без критика и ограничен
  `max_steps=6`.
- ReAct ограничен 8–20 итерациями (по умолчанию 10), имеет единый wall-clock
  timeout 5–15 секунд на всю итерацию (по умолчанию 10) и возвращает точный
  ответ `Timeout` либо `Превышен лимит итераций` при исчерпании границы.
- После каждого наблюдения ReAct вызывает критика, который допускает только
  `OK` либо `REVISE: причина`. Во всём запуске применяется не более двух
  замечаний; каждый main- и critic-вызов входит в агрегированные tokens.
- Обе реализации используют одну и ту же локальную базу знаний и безопасную
  Telegram-заглушку. Пятый кейс проверяет, что агент отказывается от prompt
  injection без выдуманного инструмента.

## Формат результатов

Каждый JSON содержит сформулированную учебную задачу, ответ, полный trace,
суммарные tokens и число revisions. В нём нет API-ключей, внутренних
инструкций или персональных обращений. Папка результатов создаётся только
после явного `--allow-external-api`.
