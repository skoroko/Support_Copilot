# Переключение бота на GPT-6 Luna, 15.10.2026

По запросу пользователя локальный backend бота переключён с GPT-5.4 mini
на **GPT-6 Luna medium** для обычных и расширенных ответов. Проверка выполнена
через настоящий HTTP backend, OpenAI API, Qdrant и PostgreSQL.

## Действующая конфигурация

| Параметр | Значение |
|---|---|
| `APP_DEFAULT_MODEL` | `gpt-6-luna` |
| `AGENT_LLM_API` | `responses` |
| `AGENT_REASONING_EFFORT` | `medium` |
| `AGENT_EXPANDED_REASONING_EFFORT` | `medium` |
| `AGENT_REASONING_TOKEN_RESERVE` | `8192` |
| `AGENT_GENERATION_TIMEOUT` | `120` секунд |
| `APP_ALLOWED_MODELS` | JSON-массив Luna и mini |
| Provider storage | `store=false` |

Значения сохранены в локальном `.env` и воспроизводятся профилем
[`compose.luna.yaml`](../compose.luna.yaml). Для обновления уже работающего стека:

```powershell
docker compose -f compose.yaml -f compose.luna.yaml up -d --no-deps --build app
```

Обычный запуск Compose также использует новые настройки локального `.env`.
Runtime image: `sha256:41de25c52af775cada7f08119cf496b04f640121fd0d97d312aa933977185e56`.
Контейнер приложения после исправления конфигурации: `running`, `healthy`,
число перезапусков `0` на момент завершающей проверки.

При первом запуске обнаружено, что Pydantic Settings требует JSON для списка
моделей из окружения: вариант через запятую в подготовленном профиле мешал
старту. Формат исправлен в профиле и локальном `.env`; последующий запуск успешен.

## Проверка запросами

| Сценарий | Результат | Обычный / расширенный ответ, с |
|---|---|---:|
| Степени свободы в цилиндрических координатах | Ответ и источники сохранены | 17.46 / 9.51 |
| Поровое давление и система координат | Ответ и источники сохранены | 8.72 / — |
| Алгоритмы нелинейного расчёта | Ответ и источники сохранены | 30.16 / 16.75 |
| Уточнение про плоскую деформацию в том же диалоге | История использована, найден источник | 8.28 / — |
| Неоднозначный вопрос о параметрах | Запрошено уточнение | 2.58 / — |
| Гарантированный SLA по неизвестному договору | Неподтверждённые сроки не выдуманы | 3.70 / — |
| Продолжение ранее сохранённого mini-диалога | Новый ответ Luna, прежняя история сохранена | 12.15 / — |

Итого: **7 обычных ответов и 2 расширения, без ошибок**. Это функциональная
проверка переключения, а не новый сравнительный benchmark качества.

- Текст SSE и источники совпадают с сохранёнными сообщениями для всех обычных ответов.
- Текст и источники обоих расширений совпадают с историей; номера цитат корректны.
- Preview расширения не меняет историю; `confirmed=false` возвращает HTTP 422.
- Повторное подтверждение возвращает тот же message id и не добавляет сообщений.
- В основном прогоне 14 вызовов модели в checkpoints: все `gpt-6-luna`,
  завершены с `stop` или `tool_calls`; сохранён usage reasoning.
- В старом диалоге checkpoints содержат прежнюю `gpt-5.4-mini-2026-03-17`
  и новую `gpt-6-luna`; последние два вызова относятся к Luna, последний завершён `stop`.
- `/ready`: HTTP 200, `status=ok`, Redis и RAG `up`.
- Из работающего контейнера бота проверены доступ к backend, авторизованное
  чтение истории и read-only Telegram `getMe`.
- Compose `config --quiet` и `git diff --check` проходят.

Корпус, embeddings и индекс не менялись; ingestion на старте выключен.
На момент этого переключения отдельный RAG API сохранял `gpt-5.4-mini`.
Следующим шагом он также переведён на Luna medium с переформулированием `none`:
[отдельный отчёт о RAG](rag_luna_rollout.md).
HTTP-контракты и архитектура не изменены, обновление диаграмм не требуется.
Проверка использует изолированные eval-профили; **сообщения в Telegram не отправлялись**,
нажатие кнопки в реальном Telegram-интерфейсе не проверялось.
