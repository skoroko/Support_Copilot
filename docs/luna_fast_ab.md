# Luna medium: Standard / Fast, 2026-10-16

Fast подтвердился на аккаунте, но на этих двух вопросах дал небольшой выигрыш за примерно двойную стоимость. Рекомендация: пока оставить рабочий Standard; Fast не устраняет повторные агентские поиски. Рабочую конфигурацию не меняли.

После сравнения пользователь подтвердил решение: оставить Standard и сохранить изменения через commit/push/merge. Это разрешение на Git workflow, без переключения runtime или включения prefetch.

## Условия

12 ответов: два прежних вопроса (Hardening Soil и граничные условия GTS NX), по три повтора каждого режима. Серийный запуск с чередованием порядка Standard/Fast; отдельный процесс и InMemorySaver на ответ. Те же замороженные истории, без Telegram и записи рабочих диалогов. Prefetch **false в обоих режимах**. Текущий локальный код одинаков; он содержит общий для обоих вариантов guard целостности табличной строки, отсутствующий в старом production image. Это сравнение режимов на одной версии, не сравнение с историческими временами production.

Профиль: `gpt-6-luna`, Responses API, `reasoning.effort=medium`, `store=false`, retry=0, generation timeout=120s. Ответный бюджет 500 + reasoning reserve 8192 = общий generation cap 8692; history window10, context budget118808, retrieval context cap24000. Различие только `service_tier=default` / `fast`. Все **40 модельных ответов** вернули ожидаемый tier:20default и20fast. Ошибок, downgrade, замен и дополнительных попыток нет.

Перед измерением одинаково прогрет локальный tokenizer (0,35–0,50с) и построен RAG (0,68–1,33с). Total ниже — время графа от запроса до готового ответа, включая все model/tool calls; запуск контейнера и эта инициализация показаны отдельно в JSON. Остаток total минус model/retrieval составляет0,04–0,09с. Во время API-прогона тесты не выполнялись. Кеш провайдера не очищался; cache-read/write usage сохранён. Нельзя непосредственно приписывать разницу со старыми cold-process замерами Fast.

## Полнота и точность

Рубрика зафиксирована до запуска в manifest. Astra вручную сверила каждый ответ с фактически процитированными выдержками. Другого модельного judge не было. Проверялись область HS/HSS, полное Modified Mohr-Coulomb, G0ref/γ0.7, зависимость жёсткости и параметры; для границ — три категории, разделение seepage/consolidation, динамическая применимость и соответствие утверждений цитатам.

Во всех6 HS-ответах сохранены корректное полное имя Modified и оговорка, что найдено описание **small strain**, а не отдельная документация базовой HS; G0ref и γ0.7 определены верно. Ни один не объявляет всю модель просто нелинейно-упругой. Все6 обзоров границ называют три основные категории. Все12 дали содержательный обзор, но это не12полностью исчерпывающих инженерных ответов: глубина различается, есть указанные оговорки применимости. Ни один обзор явно не разделил временную/частотную область динамических границ. Наличие слова «вязкие» под обсуждением EL само по себе не оценивалось как ошибка: цитируемая методология Transmitting действительно описывает их автоматическое создание на нижней/свободной границе. Не следует переносить это на любой динамический solver.

Признаков систематического ухудшения точности от Fast на этой выборке нет; доказать эквивалентность качества по двум вопросам нельзя. Детальность HS нестабильна в обоих режимах.
