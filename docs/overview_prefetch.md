# Предварительный evidence для обзорных вопросов

16.10.2026. V1 проверен на 8 live-ответах: стабильного ускорения нет.
V2 проверен на ещё 4 live-ответах: устойчивого выигрыша и сохранения качества нет.
Prefetch **выключен по умолчанию**;
production-код и профиль Luna medium/default не обновлялись.

## Изменение

При явном `overview_prefetch_enabled=true` после `begin_turn` узел
`prefetch_overview` распознаёт узкий самостоятельный обзорный вопрос.
V1 запускал два независимых поиска через прежний
`RAGService.retrieve`: описание/область применения и параметры для модели;
классификация и назначение для граничных условий. При выключенном локальном
reranker поиски параллельны; с reranker последовательны из-за общего состояния
его модели. Переводы заданы детерминированно, отдельной LLM-нормализации нет.

Результаты проходят прежние product/confidence/evidence gates. Затем пакет
чередует результаты аспектов, удаляет повторы, сохраняет дополнительные
проекции одного CHM chunk отдельными фрагментами, ограничивает общий текст
24 000 символов и назначает единые номера citations. Целые строки таблиц
сохраняются, включая одиночную строку без перевода строки. Имена моделей,
область HS small strain, страницы и CHM provenance остаются исходными.

Пакет передаётся модели как недоверенные данные рядом с вопросом; исходная
история в checkpoint не переписывается. Coverage flags — эвристика наличия
разделов, а не доказательство истины/полноты. Модель может ответить первым
вызовом или выполнить обычный прицельный поиск. Лимит итераций не уменьшен;
частичный или полный отказ prefetch не запрещает восстановление. «Подробнее»
использует сохранённый evidence без нового поиска. Отправка в Telegram и её
подтверждение не изменены.

## Область действия

Распознаются самостоятельные формулировки вида «какие граничные условия есть
в GTS NX», «расскажи про модель Hardening Soil», «что такое модель Мора-Кулона»,
«tell me about Modified Cam Clay in GTS NX». Словарь включает HS/HS small,
Mohr–Coulomb/Modified, Soft Soil/Creep, Modified Cam Clay, Hoek–Brown,
Drucker–Prager, Jardine и перечисленные в коде русские варианты. План поиска
ориентирован на GTS NX, текущий корпус проекта.

Не распознаются произвольные сокращения, неизвестные модели, «а её параметры?»,
процедурные вопросы, сравнения/составные вопросы, просьбы отправки, другой явно
названный продукт. Они проходят прежний агентный путь. Это ускорение выбранного
класса обзоров; обещания ускорить все обращения нет. Даже для распознанного
обзора новые поисковые формулировки могут дать неполную выдачу и вызвать fallback.
Дополнительный retrieval также увеличивает нагрузку на embedding/Qdrant.

## Зафиксированный live протокол V1

`scripts/compare_overview_prefetch.py`: 8 ответов = два прежних вопроса с
замороженной соответствующей историей × два повтора × prefetch off/on.
Пользователь явно разрешил 8 ответов OpenAI API с оплатой usage 16.10.2026.
Оба варианта используют один код, Luna medium Responses/default, одинаковые
ceilings, history/context budgets и исправление одиночной строки. Before
отличается только `overview_prefetch_enabled=false`. Порядок чередуется,
concurrency=1, новый процесс/память/checkpointer на каждый sample; Telegram
запрещён runner-ом. Код приложения подключается read-only в одноразовый
контейнер; рабочие app/bot не обновляются.

До первого вызова фиксируются SHA-256 кода, runner, исходных и очищенных только
от transport metadata входов. Частные ответы/evidence находятся в игнорируемом
`var/overview_prefetch_ab`; публичные результаты содержат только метаданные.
Измеряются total/model time, retrieval intervals (их объединение, поскольку
параллельные длительности нельзя складывать как wall latency), preparation,
число model/retrieval calls, usage включая reasoning/cache. Не заявляются SLA
или статистическая значимость по двум вопросам и двум повторам.

Рубрика ручной проверки зафиксирована до API:

- Границы: механические закрепления/связи, фильтрационные условия, динамические
  границы; назначение хотя бы по одному примеру на семейство; Draining Condition
  не приписывается фильтрации по общему названию меню.
- HS: роль и нелинейная жёсткость, основные группы параметров, точное имя
  Modified Mohr–Coulomb при соответствующем утверждении, явная область HS small
  strain для G0ref/gamma0.7/малых деформаций; без выдуманных гарантий.
- Для каждого фактического утверждения проверяется поддержка конкретным
  процитированным фрагментом, имена/страницы, отсутствие подмены соседней моделью.
- Отказы/ошибки и пропуски отражаются отдельно; число citations само по себе
  не является оценкой качества. Оценку выполняет Astra, без внешнего model judge.

## Результат V1: не включать

Все 8 запусков завершились ответами, без transport/retrieval отказов. Все ответы
API подтвердили `service_tier=default`. Длительности в секундах:

| Вопрос | Before, 2 повтора | V1, 2 повтора | Медиана before → V1 | Model calls before → V1 |
|---|---|---|---|---|
| HS | 24,52; 21,75 | 19,21; 58,39 | 23,13 → 38,80 | 3/3 → 1/3 |
| Граничные условия | 13,23; 14,60 | 21,05; 19,61 | 13,92 → 20,33 | 2/2 → 1/1 |

Сокращение числа model calls не обеспечило сокращения их суммарного времени:
HS median model time 15,83 → 23,09с; границы 8,99 → 11,88с. Для границ пакет
содержал 10 источников, первый вызов получал 10 198 input tokens вместо
6 772–6 898 на финальном before-вызове. Для HS одинаковый пакет 7 143 tokens
в одном повторе позволил ответить сразу, в другом вызвал два дополнительных
общих поиска базовой HS. В одном из них dense retrieval занял 20,33с при
локальном selection 0,087с. Даже без этого выброса дополнительные model calls
и retrieval не исчезают. Пакет не содержал перечня уже выполненных queries.

Other overhead составил 3,09–3,98с в семи samples и 8,30с в одном. Он включает
граф/инициализацию токенизации и не был отдельно профилирован; нельзя целиком
приписать его конкретному этапу или считать производственным SLA. Каждый
sample запускался в свежем контейнере, порядок off/on чередовался.

Полнота: оба V1 HS-ответа сохранили scope small strain, полное Modified Mohr–Coulomb,
G0ref/γ0.7 и добавили m; второй также пояснил E50ref/Eoedref/Eurref. В before
один ответ раскрывал G0ref/γ0.7, другой — m/E-модули. Оба V1 и оба before по
границам перечислили три категории без подмены фильтрации консолидацией.

Точность: новых противоречащих мануалам фактов в V1 не обнаружено, но один HS
ответ поставил citation к составному утверждению о снижении жёсткости на
фрагмент, подтверждающий лишь часть фразы; полный факт был в другом доступном
CHM evidence. В одном before HS была обрывающаяся цитата о гиперболической
зависимости и неоднозначное отнесение нелинейно-упругого поведения ко всей
модели. Один V1 boundary ответ склеил вводную фразу с основным текстом.
Поэтому «без потери качества» без оговорок не утверждается.

Данные: [v1_summary.json](../tests/eval/results/2026-10-16_overview_prefetch/v1_summary.json).
Реальные ответы и evaluated code snapshot сохранены приватно в `var/overview_prefetch_ab`.

## Узкая доработка V2

Для boundary/HS сначала выполняется один обзорный retrieval. Второй аспект
вызывается, если в возвращённом тексте отсутствует проверяемый набор: три
категории границ либо описание HS с полным Modified-именем, G0ref/γ0.7 и таблица
E50ref/Eoedref/Eurref. Это эвристика достаточности *предварительного этапа*, а не
запрет модели проверить недостающий факт. Остальные распознанные модели
сохраняют прежние два независимых аспекта. Данные не урезаются ради ускорения.

Пакет теперь показывает фактически выполненные queries/status; инструкция
отличает новый конкретный недостающий аспект от переформулировки уже выполненного
общего поиска. Ограничение scope найденным вариантом не объявляется отсутствием
других сведений во всём корпусе. Каждый факт должен получить собственную citation;
вводное сообщение о намерении отвечать не нужно.

Офлайн replay четырёх реальных V1 pools: prefetch retrieval 2 → 1 во всех четырёх;
исходные тексты и страницы сохранены. HS evidence 13 558 → 7 888 символов,
локальная оценка prompt tokens 6 927 → 5 137 (−26%); границы 21 457 → 10 663
символов, 9 982 → 6 656 tokens (−33%). Это результат отказа от избыточного второго
поиска, не усечение первого результата. Эти числа не доказывают live-скорость
или решения настоящей модели. [v2_offline.json](../tests/eval/results/2026-10-16_overview_prefetch/v2_offline.json).

Целевые V2 проверки: 56 passed; lint PASS. Полный regression: **893 passed, 11 skipped**.
Безопасный default-off отдельно проверен. Production после V1: ready200, прежний
образ `a9ae8623…`, Luna medium/Responses, prefetch-модуля нет.

Выполнен `scripts/compare_overview_prefetch_v2.py`: четыре ответа V2, два на
каждый прежний вопрос, тот же профиль и frozen history; сравнение с сохранёнными
сегодняшними четырьмя before. Это экономный контроль с временным смещением, а не
новый чередующийся A/B. Пользователь отдельно разрешил эти 4 ответа; все они
получены без transport/retrieval отказов. Всего в этом этапе 12 ответов, без
повторов попыток. Новые платные вызовы остановлены.

Медианы total before → V1 → V2: HS **23,13 → 38,80 → 23,39с**;

Стартовый пакет стал меньше, но повторные поиски настоящей модели остались.

В V2 исходная полнота/привязка к источникам не сохранилась:

- Оба HS-ответа перечислили E-модули/m, но пропустили Modified-основу и
  определения G0ref/γ0.7. Первый представил описание small strain как базовую
  HS и назвал всю модель нелинейно-упругой. Второй после трёх дополнительных
  поисков приписал базовой HS сведения из печатной страницы34 Mesh, которая
  относится к **Modified Mohr–Coulomb**: начало раздела проверено на печатной
  странице33 (физические PDF страницы35/34). Это ошибка области citation,
  даже когда отдельные инженерные свойства могут быть похожи.
- Оба boundary-ответа сохранили три категории. Первый корректно разделил
  консолидацию/фильтрацию. Второй добавил подтверждённые Nodal Head/Flux, но
  слишком широко связал вязкие границы с эквивалентно-линейным анализом:
  процитированная таблица сопоставляет вязкие границы расчёту во времени,
  передающие — частотному расчёту.

Измеренный residual V2 (`total − model − union(retrieval intervals)`):
5,17; 18,94; 3,60; 2,90с. Холодная загрузка tiktoken — возможная причина,
поскольку `count_tokens` может впервые загружать encoding, но отдельного
таймера для неё не было. **18,94с нельзя объявлять измеренным временем
токенизации.** Первый HS V2 частично совпал по времени с offline pytest;
остальные три запускались после его завершения. Это дополнительное ограничение
сравнения, и первый sample не был скрыт или заменён новым платным вызовом.

Данные: [v2_summary.json](../tests/eval/results/2026-10-16_overview_prefetch/v2_summary.json),
с manifest/hashes, stage timings, input/output/reasoning/cache usage и ручной
проверкой каждого ответа. Reasoning входит в output usage и не суммируется с
ним повторно. Стоимость здесь не рассчитывалась.

**Решение: ни V1, ни V2 не включать в рабочий контур. Цель ускорения без
потери качества не достигнута.** Код эксперимента сохранён opt-in, модель,
reasoning, tier и рабочие диалоги не изменены; production по-прежнему не
содержит prefetch-модуль. Никаких commit/push/rollout не выполнено.

Обоснованный следующий шаг внутри этого подхода — перед генерацией сохранять
проверяемую принадлежность каждого фрагмента к точной модели/варианту и разделу
мануала. Сейчас параметры CHM могут поступать отдельной таблицей без имени
варианта, а PDF-фрагмент может начинаться после заголовка другого раздела.
Проверка наличия слов/параметров не доказывает полноту именно запрошенной модели.
Сначала нужен offline контракт на такую принадлежность и различение новых
фактов от повторного общего поиска, затем новая отдельная проверка. Простое
усиление prompt или запрет дополнительных поисков доказанного решения не дали.
