# Домашнее задание 1.2: экономика ИИ-решения

Задача: рассчитать экономику Support Copilot и выбрать стратегию запуска:
облако, локально или гибрид.

## Сценарий

Support Copilot используется как внутренний помощник инженеров техподдержки.
Он готовит черновики ответов, помогает классифицировать обращения и подсказывает
эскалацию.

| Параметр | Значение |
| --- | ---: |
| Пользователи | 12 инженеров поддержки |
| Запросов на пользователя в день | 25 |
| Всего запросов в день | 300 |
| Дней в месяце | 30 |
| Запросов в месяц | 9 000 |
| Средний input | 900 токенов |
| Средний output | 350 токенов |
| Input в месяц | 8.1M токенов |
| Output в месяц | 3.15M токенов |

Формула:

```text
monthly_cost = input_mtok * input_price + output_mtok * output_price
```

## Точка безубыточности

Точка безубыточности показывает, при каком объеме запросов локальный сервер
становится дешевле облачной модели.

| Облачная модель | Break-even, запросов в месяц | Break-even, запросов в день |
| --- | ---: | ---: |
| OpenAI `GPT-5.4` | 19 911 | 664 |
| Google `Gemini 2.5 Pro` | 32 288 | 1 076 |
| OpenAI `GPT-5.4 mini` | 66 369 | 2 212 |
| DeepSeek `deepseek-v4-flash` | 666 652 | 22 222 |

При текущем сценарии 9 000 запросов в месяц локальный сервер дороже всех
рассмотренных облачных вариантов.

## Выбор стратегии

Для текущего объема я выбрал бы гибридную стратегию с облаком как основным
режимом. Базовые обращения и черновики ответов выгодно обрабатывать через
`GPT-5.4 mini` или другой бюджетный облачный вариант, а сложные случаи
маршрутизировать во флагманскую модель только при необходимости. Локальную модель
имеет смысл оставить как fallback для офлайн-демо, приватных экспериментов и
случаев, где нельзя отправлять данные во внешний API. Полностью локальный сервер
экономически оправдывается только при росте нагрузки примерно выше 20 000
запросов в месяц для флагманского облака или выше 66 000 запросов в месяц для
`GPT-5.4 mini`.
