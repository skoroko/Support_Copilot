## Проверка единственного расхождения

Ответ №33 — «В предоставленной базе знаний нет достаточно надёжных сведений
для ответа на этот вопрос». Regex вернул `no`, судья — `yes`.
Это отказ по недостатку информации, без маркера, названия документа или явной
ссылки. По строгому критерию наличия явной ссылки judge дал ложноположительную
оценку. Первоначальный verdict `yes` сохранён: ручная проверка не переписывает
результат модели.

Следовательно, 34 положительных verdict не означают 34 корректных цитирования.
Этот опыт проверяет учебную LLM-метрику и показывает её ограничение. Grounding,
достоверность источника, соответствие утверждения процитированному фрагменту
и правильность ответа требуют отдельной проверки по контекстам. Совпадение
с regex также не является такой проверкой.

Полные [отдельные метрики](results/citation_judge_2026-10-21.json) содержат номера
строк, SHA-256 ответов, verdict обеих метрик, статусы, latency и usage.
Тексты ответов и исходные контексты в этот файл не дублируются.

## Воспроизводимый запуск

Команда ниже повторно вызовет внешний API и создаст отдельный результат;
выполнять её следует только в рамках разрешённого бюджета вызовов:

```powershell
python scripts/evaluate_citation_judge.py `
  --input tests/eval/results/2026-09-12_185629_baseline_batched.csv `
  --output homework_5_6/results/citation_judge_new_run.json `
  --env-file .env --limit 34 --allow-external-api
```

В данном прогоне использовано уже существующее Python 3.13 `.venv` проекта.
Скрипт ограничивает выборку 34 ответами, сохраняет каждый факт ошибки и требует
явный флаг внешних вызовов. Два офлайн-теста проверяют лимит и сохранение
ошибки между успешными строками без потери checkpoint.
